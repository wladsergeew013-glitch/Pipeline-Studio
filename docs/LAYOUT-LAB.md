# Локальный стенд раскладки

Стенд запускает настоящий редактор на отдельной копии документа. Каждый сценарий
начинается с исходного снимка. Материалы и исходный файл не изменяются.

```powershell
py tools/create_layout_lab.py --document 'F:\Схема.html' --output 'qa\Layout-Lab.html'
Start-Process 'qa\Layout-Lab.html'
```

В панели сверху выбираются лист и связи общего блока: все ветви, соседние пары,
четыре условия или пары из этих четырёх. Можно переключить уплотнение,
автоматические интервалы и разрешение пересечений, свернуть/развернуть схему,
перейти к выбранному участку и скачать JSON-отчёт. При невозможности безопасного
применения прежняя раскладка сохраняется, а причина показывается в отчёте.

Проверка различает наложение блоков, линию через чужой блок и пересечение
независимых связей. Общий порт и намеренно общая начальная линия не считаются
пересечением. Комментарии, примечания и прикреплённые изображения учитываются как
видимые препятствия. Изображение может перекрывать собственный блок, к которому
оно прикреплено. Общие линии гребёнки исключаются из проверки независимых связей. Проверка ромба
использует консервативный прямоугольник его границ. Уже существующие дефекты
перечисляются отдельно от добавленных выбранным сценарием.

## Автоматический прогон

```powershell
py build_portable.py
$env:STUDIO_PRIVATE_DOCUMENT='F:\Схема.html'
node tests/browser_symmetry_lab.js
```

Прогон выполняет четыре сочетания уплотнения и интервалов для каждого участка
на каждом листе, снимает основные участки и все неуспешные результаты, проверяет
симметрию по координатам портов, цикл сворачивания/разворачивания и применение
четырёх связей через инспектор с undo/redo. Снимки и машиночитаемый отчёт находятся
в `qa/symmetry-lab/`. Без переменной используется публичная демонстрационная схема.
Личные схемы, снимки и результаты находятся в игнорируемом `qa/` и не публикуются.

## Ручные последовательности

Стенд автоматически добавляет результат в отчёт после завершения перетаскивания.
«Скачать копию варианта» создаёт отдельный файл для сравнения; исходный документ
обновляется обычным «Сохранить» в редакторе EXE после открытия через «Открыть HTML».

```powershell
$env:STUDIO_INTERACTION_DOCUMENT='C:\Папка\Изменённая схема.html'
node tests/browser_interaction_sequences.js
```

Проверки выполняют движения настоящей мышью вверх/вниз и вправо/влево в четырёх
режимах обоих листов. После каждого жеста проверяются новые конфликты, направление
и предел движения выбранного блока и симметрия. После последовательности проверяются
сворачивание/раскрытие, undo/redo, свойства одной связи, её группа, ручной сегмент
и сохранение с повторным открытием. Без переменной используется публичная схема
с обратным порядком исходных координат. Результаты находятся в
`qa/interaction-sequences/private/` или `qa/interaction-sequences/public/`.

## Расстояние между пайплайнами

В нижней панели откройте «Размещение цепочек», включите «Убирать свободные
промежутки» и настройте ползунок «Расстояние между пайплайнами»: 24–600 px,
по умолчанию 64 px. Значение хранится в `layoutOptions.pipelineGap` текущего
листа. Предпросмотр использует полные видимые границы цепочек, включая примечания
и изображения. Внутренние ответвления также раздвигаются при наложении таблиц.
Ручные координаты сохраняются; один жест ползунка отменяется одним Ctrl+Z.

Ползунок настраивает промежуток между пайплайнами. Интервал между выходами
условия или четырьмя выбранными связями остаётся отдельным свойством симметрии.
Простой ручной изгиб связи внутри такой группы задаёт положение парного изгиба.
Стенд записывает ошибки парных изгибов и фактическое значение отступа в отчёт.

```powershell
node tests/test_pipeline_spacing.js
node tests/browser_render_spacing.js
```

Отрисовка повторно использует проверенные геометрию и маршруты при перетаскивании.
Неизменившиеся узлы и SVG сохраняют DOM; замеры кнопок выполняются одним пакетом
при изменении размеров. Панорамирование и масштабирование используют готовую
геометрию.

Для повторяемого локального замера скорости выполните:

```powershell
node tools/measure_rendering.js --document "C:\path\diagram.html" --output qa/render-performance.json
```

Можно указать прежний редактор через `--editor` и сравнить одну схему на двух
версиях. Измеряются прогретые обработчики JavaScript и DOM при отрисовке,
масштабировании и настоящем движении мышью; это не измерение частоты экрана.
Проверка создаёт рабочую копию в памяти и не сохраняет исходный документ.

Для движения в тесный коридор можно задать расстояние жеста в пикселях:

```powershell
node tools/measure_rendering.js --document "C:\path\diagram.html" --dx -420 --dy 0 --output qa/render-close.json
```

`tests/browser_shared_symmetry.js` дополнительно снимает общий пайплайн при
закрытой/открытой АР и четыре связи до/после реального сближения. Проверяются
полные формы парных маршрутов, центр обеих сторон гребёнки и отсутствие новых
конфликтов во всей схеме в каждом кадре. Для собственной схемы задайте
`STUDIO_INTERACTION_DOCUMENT`; результаты сохраняются в `qa/shared-symmetry/private/`.

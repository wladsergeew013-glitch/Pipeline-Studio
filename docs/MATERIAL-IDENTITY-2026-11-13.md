# Pipeline Studio 0.7.19: идентичность источников

Выпуск от 13 ноября 2026 года на базе `0837a8ecdd740fe7ae206f0b130d8df081150429` (0.7.18). Повторное ревью подтвердило закрытие двух прежних P1 и десяти из двенадцати первоначальных замечаний. Здесь исправлены четыре новых P2, включая оставшиеся случаи переносимости.

## Изменения

- Выбор файла возвращает адрес, вычисленный от текущего HTML, включая `../External/Budget.xlsx`. Если достоверный относительный адрес сформировать нельзя, он остаётся пустым. Basename не подменяет адрес выбранного внешнего файла; открытие, проверка, Проводник и подписанная ссылка используют тот же источник.
- Перед упаковкой HTML оригинал и PDF-превью разрешаются относительно открытого документа тем же файловым мостом, что используется для просмотра. Только затем вычисляются адреса от целевого HTML. Обновляются фактические абсолютные пути и ссылка приложения.
- Материалы только с `path` или `previewPath` разрешаются от прежнего расположения HTML и получают корректный адрес для Save As. Более поздняя замена материала не затирается результатом начатого сохранения. Черновик и история Undo/Redo получают ту же базу путей.
- Копирование свободной гребёнки переносит числовую ручную ось вместе с подграфом. Проверены вертикальная и горизонтальная магистрали, действие Ctrl+D и геометрические конфликты копии.

Разрешения файлового моста и проверки выхода за предоставленные каталоги сохранены. На разных дисках относительный адрес может отсутствовать; тогда сохраняется фактический абсолютный источник. Файлы материалов остаются внешними.

## Проверки

| Проверка | Результат |
|---|---|
| Штатный `python tests/run_checks.py --browser` на локальном Edge | 982 JS-проверки и 61 Python-тест; один тест реального LibreOffice пропущен |
| `node tests/test_review_regressions.js` после добавления Undo/Redo | 16 сценариев, включая прежние P1, замену во время Save As, оба направления ручной оси |
| `node tests/test_desktop_files.js` | 34 проверки, включая двух одноимённых соседей, open/stat/folder/link и отсутствие выдуманного basename |
| `python tests/test_local.py` | 27 HTTP-проверок, включая тот же выбор внешнего файла |
| `node tests/browser_review_desktop.js` на финальном EXE | 15 проверок: перенос → Save → закрытие → открытие, относительные оригинал и PDF-превью → Save As → Undo/Redo → открытие, настоящий выбор одноимённого внешнего файла |
| `node tests/browser_desktop.js` на финальном EXE | 23 штатные проверки, включая PDF, изображение, тестовое видео и оригиналы |
| `node --check` изменённых JS/CJS; Python `py_compile`; `git diff --check` | Пройдено |

Число 982 относится к полному прогону до дополнительного сценария Undo/Redo. Окончательный набор из 16 VM-сценариев и финальный EXE затем проверены отдельно. Междисковые Windows-адреса проверены в VM; полный файловый цикл EXE выполнен на одном диске с разными папками. Все данные искусственные; частные рабочие документы не изменялись.

Контрольные суммы генерируются после сборки. До слияния требуются Linux и Windows CI; Windows CI включает сборку EXE и три варианта пути переносимого приложения. Ссылки на принятый коммит и CI приводятся в описании выпуска.

Реальный LibreOffice отсутствует. Его прежние HTTP-регрессии с управляемым конвертером сохранены.

## Обновление

Откройте документ в новом EXE и сохраните его, чтобы обновить встроенный просмотрщик и адреса материалов. При передаче копируйте материалы с сохранением относительного расположения. Схема данных остаётся версии 6.

# Pipeline Studio 0.7.20: сохранение и совместимость

База: main / dcf2870a21cde086e788effdfcdf8f52cfee3eb0 (0.7.19). Эта версия реализует изменения по ревью R01–R34 и X01–X02.

## Документы и источники

Открытие готовит модель, файловые привязки и параметры вида отдельно. Только последняя начатая операция может заменить активный документ. Правки прежнего документа, сделанные во время подготовки нового, сбрасываются в его собственный черновик перед переключением. Запоздалые загрузки не прикрепляются к другому документу или листу; изменение реестра не подменяется запоздалым ответом.

Сохранения HTML одного документа выполняются последовательно, включая выбор места. Каждая следующая операция использует новое положение HTML. Перед сохранением, экспортом и закрытием применяется видимая правка ячейки или подписи. История хранит привязки файлов и handles вместе с моделью; возврат по Undo/Redo очищает кеш URL. Выбранный пользователем handle имеет приоритет перед одноимённым файлом подключённой папки и сохраняется в браузерном черновике. Разрешения браузера после перезапуска могут потребовать повторного предоставления доступа.

Лимит открываемого и сохраняемого HTML — 40 МиБ в UTF-8. Превышение отклоняется до изменения файла. Для HTTP-моста оболочка JSON может быть больше из-за экранирования, но предел самого HTML тот же.

## Серверное хранилище и API

Авторитетная запись — `STUDIO_DATA/state.json`: проект, реестр и предыдущая версия проекта. Временный файл сбрасывается на диск и заменяет состояние одним `os.replace`; ошибка до замены сохраняет прежний проект и реестр. Все изменяющие маршруты используют общий LOCK. При первом запуске старые `project.json`, `materials.json` и `project.previous.json` читаются автоматически; исходные файлы остаются на месте. После миграции правки этих старых файлов не меняют активное состояние.

Резервная копия держит тот же LOCK и содержит согласованные `project.json` / `materials.json`, прежнюю версию, публикации и файлы. Для восстановления распакуйте её в **новый пустой каталог**, задайте его как STUDIO_DATA и запустите сервер: он создаст state.json из этих данных. Исходный каталог оставляйте как резервную копию.

Редактор выполняет сохранение, загрузку и создание превью в одной очереди серверных операций документа: собственная долгая загрузка не конфликтует с собственным автосохранением, а снимок проекта готовится в начале своей очереди. Любая запись реестра, загрузка или создание превью увеличивает общую `revision`. PUT проекта проверяет её точное совпадение. Загрузка из редактора передаёт `X-Project-Revision`; конвертация проверяет ревизию также после завершения. Запоздалый клиент не может объявить устаревшую схему текущей через ответ загрузки.

GET проекта/реестра и ответ загрузки выдают `baseVersion` материала. При изменении существующей записи PUT должен передать эту исходную версию; сервер требует точного совпадения и сам назначает следующий номер. Клиентский `version + 1` не доказывает актуальность. Неизменённые записи допустимы без baseVersion; новые записи получают версию 1. PUT проекта возвращает `materialVersions`, которые редактор принимает как новую базу, сохраняя более поздние локальные правки. Конфликт возвращает 409 без частичной записи.

Публикации сохраняют снимок схемы и используют живой реестр. Доступ читателя включает ссылки из HTML блоков/ячеек и транзитивные `previewMaterial`; циклы зависимостей обходятся один раз. Несвязанные материалы остаются недоступны.

## Контракты импорта и отображения

Числа, попадающие в оформление HTML/SVG, и значения перечислений проверяются до старой нормализации. Версия материала — положительное безопасное целое. Дробные размеры шрифта и толщины линий допустимы; прежние числовые строки размера шрифта блока сохраняют совместимость. Неизвестный wordWrap отклоняется. Для edge.width исходный путь через DOM.style сам по себе не подтверждал HTML-инъекцию; общая числовая проверка теперь применяется к нему тоже.

MIME проверяется и при записи, и перед началом ответа файла. Тип для политики браузера сравнивается без параметров и без учёта регистра. SVG получает sandbox, включая пустое или отсутствующее имя файла. GET/HEAD и Range используют одно правило.

XML-парсер запрещает DTD до раскрытия сущностей, включая UTF-16 и сжатые страницы; обычные Unicode и предопределённые XML-сущности допустимы. Один импорт имеет суммарный бюджет 20 МиБ для контейнера и распакованных страниц, 128 страниц, 100000 XML-элементов, глубину XML и родителей не более 128. Общий кооперативный дедлайн — 10 секунд: он проверяется при разборе XML и текста, обработке элементов, родителей и графа. Превышение отклоняет весь импорт. Повтор ID внутри листа отклоняется: иначе небольшой XML мог многократно разворачивать одну таблицу. Ошибочный XML/base64/DEFLATE возвращает 400, импорт не обрезает данные молча.

Таблица распознаётся по структуре строк и ячеек с маркером `shape=table` или `childLayout=tableLayout`; пустая shape=table также допустима. Неподдержанная структура сохраняется отдельными объектами и отмечается в отчёте. Swimlane представляется самостоятельным блоком с сохранёнными дочерними объектами и конечными точками связей. Упрощение поведения контейнера явно перечисляется в отчёте. Импорт сохраняет стрелки в начале и конце. Печатная схема использует ту же геометрию, реальные цвета/толщины и правильное направление начальной стрелки. Сообщение импорта больше не обещает несуществующую копию XML.

## Приёмочные команды

- `python tests/run_checks.py --browser`: модель, HTTP, файловые мосты и Edge.
- `node tests/browser_review_desktop.js`: упакованный EXE, сохранения и переносы, включая параллельный Save As.
- `node tests/browser_desktop.js`: штатные действия Windows-приложения.
- `node tests/browser_portable_transfer.js`: перенос настоящего portable launcher.
- `python tools/checksums.py`: манифест публичных исходников и HTML.

Тесты используют синтетические документы и отдельные профили; пользовательские документы и регистрация протокола не изменяются. Реальный LibreOffice отсутствует: соответствующая необязательная проверка пропускается; серверные гонки конвертации проверяются управляемым конвертером. CI выполняет браузерный набор на Linux и сборку/проверки EXE на Windows. Результаты CI и серверные SHA256 релизных файлов фиксируются при публикации.

Локальная приёмка окончательного кандидата: 1034 JS-проверки полного набора; 71 Python-тест (70 прошли, один пропущен без LibreOffice); 17 проверок новых цепочек в EXE, 23 штатных desktop-проверки и три расположения portable launcher. Пять файлов ASAR побайтно сверены с исходниками.

При дополнительных локальных portable-прогонах принудительная распаковка и тестовый профиль внутри OneDrive дали ранние таймауты старта до создания профиля. Распакованные 80 файлов имели ожидаемые размеры, EXE и ASAR совпали по SHA256, прямой запуск этой копии прошёл 17 проверок. Контроль того же бинарника с обычным системным TEMP прошёл три сценария без увеличения предела 45 секунд. Поэтому штатный тест изолирует runtime-профили в системном TEMP, оставляя EXE и HTML в исходной папке доставки; кириллица, строчная буква диска и спецсимволы сохранены. Точная причина задержки при принудительном TEMP в OneDrive не установлена; эти неудачные попытки не считаются успешной приёмкой.
